# よくある質問

## 性別を切り替えても BMI が変わらないのはなぜ？

**BMI の定義に性別が入っていない**からだ：

```
BMI = 体重(kg) ÷ 身長(m)²
```

これは WHO の標準定義で、体重と身長にしか関係しない。**身長が変われば BMI は変わる**が、性別では変わらない。

実際に性別で変わるのは体組成だ：

| 指標 | 男性 | 女性 |
| --- | --- | --- |
| 体脂肪率 | Deurenberg：`1.10×BMI + 0.23×年齢 − 11.22`（インピーダンスは不使用）| Segal：インピーダンスが必要。`(i1+i2)×0.675` で合成 |
| 水分率 | 除脂肪体重 × 0.7185 | 除脂肪体重 × 0.8475 |
| タンパク質 | 体重 × 0.163 | 体重 × 0.05 |
| 骨格筋率 | 筋肉量 × 0.548 | 筋肉量 × 0.651 |
| 皮下脂肪 | 体脂肪 × 0.7165 | 体脂肪 × 0.72 |

同じデータ（55.75kg / 163cm / 24 歳 / インピーダンス 430+387）で：男性 **17.4%**、女性 **22.2%**、4.8 ポイントの差になる。

## 性別や身長を変えたのに、履歴記録の指標が変わらない？

初期バージョンには 2 つの不具合があった（修正済み）：

1. BMI が**記録に保存された古い身長**を使っており、現在のプロフィールを使っていなかった
2. インピーダンスの無い記録は再計算時にそのまま飛ばされ、プロフィールがまったく更新されなかった

現在：記録が選択中のメンバーに属する場合、一律で**最新のプロフィール**からリアルタイムに計算する。身長／性別／年齢を変えると即座に反映される。

## インピーダンスがずっと 0 / 「今回の測定では体インピーダンスが取れていない」と表示される

インピーダンスは**物理的な条件だけで決まり**、コマンドで有効にできるものではない：

- **両足を裸足で**同時に 4 つの電極パッドに当てる必要がある
- 片足、靴下、足裏の乾燥 → 必ず 0
- バッテリー残量が極端に少ない（約 10%）ときも失敗しうる

`04 d6` コマンドはリアルタイムパケットの頻度を上げるだけで、**インピーダンスのスイッチではない**（A/B 対照実測で検証）。

## バッテリー表示が 10% 前後なのは正常？

正常だ。真の残量はリアルタイムパケット `data[11]` の下位 7 ビットで、待機時の実測最頻値が **10%** になる。

注意：この秤には標準の `0x2A19` バッテリーサービスが**無く**、そのキャラクタリスティックを読むとゴミ値（たとえば 77%）が返る。本アプリは採用しない。

## 秤に乗るたびに「履歴記録」が出る？

これは**正常な仕組み**だ：秤に乗るたびに新しい記録が生まれ、次に接続したときに秤が「未同期」の記録を送ってくる。

- 送出が完了すると秤内部で同期済みと印付けされ、再送はされない
- 同じ記録の BLE 重複配送は `時刻_体重` で重複排除され、二重に保存されない
- **秤に削除コマンドは無い**（公式の書き込みコマンド 29 件を全数調査）。したがって接続中に途中でプロセスを殺さないこと。保存し損ねると永久に失われる

## 秤が見つからない / スキャンが遅い

順に切り分ける：

1. **軽く踏んで起こす**：秤はスリープ中にアドバタイジングしない。起こして画面が点灯してから継続的に送信する
2. **権限の確認**：Android 12+ は「付近のデバイス」+「位置情報」が必要で、`adb shell pm grant` で追加付与できる
3. **UUID の事前フィルタを使わない**：実測では MIUI でサービス UUID によるフィルタが逆に秤を取りこぼす。本プロジェクトは全量スキャン + コールバック絞り込み
4. **`neverForLocation` を付けない**：この flag があると Android 12+ がこの秤の beacon アドバタイジングをフィルタする（logcat に `Skipping data matching denylist` が出る）

## 名前を変えたらデータが「消えた」

記録に保存されているのは**メンバー名**（`record.unit`）で、改名時に同期しなければ旧記録は旧い名前のまま残る。

- 新しいバージョンでは改名時に自動で同期する（`renameRecordOwner`）
- 壊れてしまったデータは **設定 → メンバー管理 → 記録の帰属を修復** で復元できる：旧い名前と**残留したプロフィール（性別／身長／年齢）**および件数が一覧表示され、移行先のメンバーを選べば割り当て直せる

## 接続直後に切れる / 再接続を繰り返す

初期バージョンでは接続確立の瞬間に `disconnected` を 1 回誤報し、再接続が走る → 同一セッションでハンドシェイクが 2 回 → 秤が新しい同期セッションとみなして履歴を再送していた。

修正済み：再接続の前に `isConnected` を再確認し、`_connecting` の排他ガードを入れた。

## スマホ上に同名の AFU アプリが 2 つある

旧 RN 版のパッケージ名は `com.aiyue.afuscale`、Flutter 版は `com.aiyue.afu_scale` で、ランチャー上の名前はどちらも AFU。

アプリを開いて下部に「データ / 設定」の 2 つのタブがあるかを見る——あれば Flutter 版。
