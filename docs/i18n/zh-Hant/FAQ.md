# 常見問題

## 為什麼切換性別 BMI 不變？

因為 **BMI 的定義裡沒有性別**：

```
BMI = 體重(kg) ÷ 身高(m)²
```

這是 WHO 標準定義，只與體重和身高有關。**身高變了 BMI 就會變**，性別不會。

真正隨性別變化的是體成分：

| 指標 | 男性 | 女性 |
| --- | --- | --- |
| 體脂率 | Deurenberg：`1.10×BMI + 0.23×年龄 − 11.22`（阻抗不參與）| Segal：需阻抗，`(i1+i2)×0.675` 合成 |
| 水分率 | 去脂體重 × 0.7185 | 去脂體重 × 0.8475 |
| 蛋白質 | 體重 × 0.163 | 體重 × 0.05 |
| 骨骼肌率 | 肌肉量 × 0.548 | 肌肉量 × 0.651 |
| 皮下脂肪 | 體脂 × 0.7165 | 體脂 × 0.72 |

同一組資料（55.75kg / 163cm / 24歲 / 阻抗 430+387）：男性 **17.4%**、女性 **22.2%**，差 4.8 個百分點。

## 改了性別/身高，歷史記錄指標沒變？

早期版本有兩個缺陷（已修）：

1. BMI 用的是**記錄裡存的舊身高**，不是目前檔案
2. 無阻抗記錄在重算時被直接跳過，檔案根本沒更新

現在：記錄屬於目前選取成員時，一律按**最新檔案**即時計算；改身高/性別/年齡會立即反映。

## 阻抗一直是 0 / 提示「本次未測得體阻抗」

阻抗**只由物理條件決定**，不是命令能開啟的：

- 必須**雙腳赤腳**同時踩住四個電極片
- 單腳、穿襪子、腳底太乾 → 必定 0
- 電量過低（約 10%）時也可能失敗

`04 d6` 命令只提高即時封包頻率，**不是阻抗開關**（A/B 對照實測驗證）。

## 電量顯示 10% 左右正常嗎？

正常。真電量取即時封包 `data[11]` 的低 7 位，待機時實測眾數就是 **10%**。

注意：這個秤**沒有**標準 `0x2A19` 電池服務，讀那個特徵會拿到垃圾值（如 77%），本應用程式不採信。

## 每次上秤都有「歷史記錄」？

這是**正常機制**：每次上秤產生新記錄，下次連線時秤把「未同步」的記錄推出來。

- 推送完成後秤內部標記已同步，不會重推
- 同一條記錄的 BLE 重複廣播會按 `時間_體重` 去重，不會重複入庫
- **秤沒有刪除命令**（官方 29 條寫命令全查過），所以連線期間別中途殺行程，漏存即永久遺失

## 掃描不到秤 / 掃描很慢

按順序排查：

1. **輕踩喚醒**：秤休眠時不廣播；喚醒後螢幕亮起才會持續發送
2. **確認權限**：Android 12+ 需要「鄰近裝置」+「位置資訊」，`adb shell pm grant` 可補授
3. **不用 UUID 前置過濾**：實測 MIUI 上用服務 UUID 過濾反而漏掉秤，本專案是全掃描 + 回呼篩選
4. **不要加 `neverForLocation`**：該 flag 會讓 Android 12+ 過濾掉此秤的 beacon 廣播（logcat 可見 `Skipping data matching denylist`）

## 改名之後資料「消失」了

記錄裡存的是**成員名字**（`record.unit`），改名時若不同步，舊記錄仍掛在舊名字下。

- 新版本改名會自動同步（`renameRecordOwner`）
- 已被改壞的資料可用 **設定 → 成員管理 → 修復記錄歸屬** 復原：會列出舊名字及**殘留的檔案（性別/身高/年齡）**和筆數，選個目標成員即可歸過去

## 連線後馬上斷線 / 反覆重連

早期版本在連線建立的瞬間會誤報一次 `disconnected`，觸發重連 → 同一個工作階段握手兩遍 → 秤當作新同步工作階段重推歷史。

現已修：重連前複查 `isConnected`，並加 `_connecting` 並發守衛。

## 手機上同名的兩個 AFU 應用程式

舊 RN 版套件名 `com.aiyue.afuscale`，Flutter 版 `com.aiyue.afu_scale`，桌面名稱都叫 AFU。

進應用程式後看底部是否有「資料 / 設定」兩個 tab —— 有就是 Flutter 版。
