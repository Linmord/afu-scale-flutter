# 常见问题

## 为什么切换性别 BMI 不变？

因为 **BMI 的定义里没有性别**：

```
BMI = 体重(kg) ÷ 身高(m)²
```

这是 WHO 标准定义，只与体重和身高有关。**身高变了 BMI 就会变**，性别不会。

真正随性别变化的是体成分：

| 指标 | 男性 | 女性 |
| --- | --- | --- |
| 体脂率 | Deurenberg：`1.10×BMI + 0.23×年龄 − 11.22`（阻抗不参与）| Segal：需阻抗，`(i1+i2)×0.675` 合成 |
| 水分率 | 去脂体重 × 0.7185 | 去脂体重 × 0.8475 |
| 蛋白质 | 体重 × 0.163 | 体重 × 0.05 |
| 骨骼肌率 | 肌肉量 × 0.548 | 肌肉量 × 0.651 |
| 皮下脂肪 | 体脂 × 0.7165 | 体脂 × 0.72 |

同一组数据（55.75kg / 163cm / 24岁 / 阻抗 430+387）：男性 **17.4%**、女性 **22.2%**，差 4.8 个百分点。

## 改了性别/身高，历史记录指标没变？

早期版本有两个缺陷（已修）：

1. BMI 用的是**记录里存的旧身高**，不是当前档案
2. 无阻抗记录在重算时被直接跳过，档案根本没更新

现在：记录属于当前选中成员时，一律按**最新档案**实时计算；改身高/性别/年龄会立即反映。

## 阻抗一直是 0 / 提示「本次未测得体阻抗」

阻抗**只由物理条件决定**，不是命令能开启的：

- 必须**双脚赤脚**同时踩住四个电极片
- 单脚、穿袜子、脚底太干 → 必定 0
- 电量过低（约 10%）时也可能失败

`04 d6` 命令只提高实时包频率，**不是阻抗开关**（A/B 对照实测验证）。

## 电量显示 10% 左右正常吗？

正常。真电量取实时包 `data[11]` 的低 7 位，待机时实测众数就是 **10%**。

注意：这个秤**没有**标准 `0x2A19` 电池服务，读那个特征会拿到垃圾值（如 77%），本应用不采信。

## 每次上秤都有"历史记录"？

这是**正常机制**：每次上秤产生新记录，下次连接时秤把「未同步」的记录推出来。

- 推送完成后秤内部标记已同步，不会重推
- 同一条记录的 BLE 重复广播会按 `时间_体重` 去重，不会重复入库
- **秤没有删除命令**（官方 29 条写命令全查过），所以连接期间别中途杀进程，漏存即永久丢

## 扫描不到秤 / 扫描很慢

按顺序排查：

1. **轻踩唤醒**：秤休眠时不广播；唤醒后屏幕亮起才会持续发送
2. **确认权限**：Android 12+ 需要「附近设备」+「位置信息」，`adb shell pm grant` 可补授
3. **不用 UUID 前置过滤**：实测 MIUI 上用服务 UUID 过滤反而漏掉秤，本项目是全扫描 + 回调筛选
4. **不要加 `neverForLocation`**：该 flag 会让 Android 12+ 过滤掉此秤的 beacon 广播（logcat 可见 `Skipping data matching denylist`）

## 改名之后数据"消失"了

记录里存的是**成员名字**（`record.unit`），改名时若不同步，旧记录仍挂在旧名字下。

- 新版本改名会自动同步（`renameRecordOwner`）
- 已被改坏的数据可用 **设置 → 成员管理 → 修复记录归属** 恢复：会列出旧名字及**残留的档案（性别/身高/年龄）**和条数，选个目标成员即可归过去

## 连接后马上断线 / 反复重连

早期版本在连接建立的瞬间会误报一次 `disconnected`，触发重连 → 同一个会话握手两遍 → 秤当作新同步会话重推历史。

现已修：重连前复查 `isConnected`，并加 `_connecting` 并发守卫。

## 手机上同名的两个 AFU 应用

旧 RN 版包名 `com.aiyue.afuscale`，Flutter 版 `com.aiyue.afu_scale`，桌面名称都叫 AFU。

进应用后看底部是否有「数据 / 设置」两个 tab —— 有就是 Flutter 版。
